# record_sop_video

面向 NVIDIA Jetson Orin NX 的双路 RTSP 事件视频过滤与保存系统。

系统通过预训练的人员检测和手部关键点模型判断“人员出现且手部进入固定工作区”事件，只保存有效操作时段的原始视频。项目以低漏录、低资源占用和 GPU 全链路处理为主要目标，尽量避免重新标注数据和训练模型。

> 当前状态：架构设计阶段，尚未提供可运行实现。

## 目标场景

- 两路固定机位 RTSP 摄像头
- 单路 1920×1080 视频
- NVIDIA Jetson Orin NX 边缘部署
- 固定多边形工作区 ROI
- 手进入工作区后开始保存，离开一段时间后停止
- 保存原始 H.264/H.265 视频，不绘制检测框，不重新编码

## 核心流程

```text
RTSP demux
 ├─ 原始压缩包 → GOP 环形缓存 → 事件触发后直接封装 MP4
 └─ NVIDIA 硬件解码 → NV12 GPU 表面
                         ↓
                    CUDA 转 RGB
                         ↓
              CUDA 裁剪/缩放/归一化
                         ↓
              TensorRT 人员检测与姿态推理
                         ↓
               C++ ROI 判断与录像状态机
```

视频像素从硬件解码输出到 TensorRT 输入始终保留在 GPU。CPU 只处理码流控制、时间戳、检测框、手部关键点和状态机，不接收完整视频帧。

## 技术方案

- **视频输入与封装：** FFmpeg、RTSP、H.264/H.265 remux
- **硬件解码：** Jetson NVIDIA V4L2 decoder
- **GPU 图像处理：** CUDA，NV12→RGB、裁剪、缩放、letterbox、归一化
- **推理：** TensorRT FP16
- **人员检测：** RT-DETR-R18 预训练模型
- **关键点：** RTMPose/RTMW WholeBody 预训练模型
- **业务逻辑：** C++ 固定 ROI 几何判断与带滞回的录像状态机
- **预录：** 原始压缩包 GOP 环形缓存

## 默认事件策略

- 至少 12 个高置信度手部关键点有效
- 至少 60% 的有效关键点进入工作区
- 连续满足约 0.5 秒后触发
- 保存触发前约 5 秒原始视频
- 双手离开工作区约 8 秒后结束
- 短暂离开不会立即切分录像

这些参数均计划通过配置文件调整，不需要重新训练模型。

## 设计原则

1. 关键操作召回率优先，允许保存少量冗余内容。
2. 推理降频不能影响原始码流缓存与录像。
3. 视频保存采用原码流 remux，避免重编码损失与额外负载。
4. 禁止在正常推理路径中把完整图像下载到 CPU。
5. 两路摄像头故障、触发和录像生命周期相互隔离。
